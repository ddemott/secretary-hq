## 🔴 HIGH — `/tenants/:id/update-config` call-transfer/disclosure hijack risk (2026-09-16, roady audit)

**Highest-severity finding of the 2026-09-16 audit sweep — called out in its own section, not blended into the list below, because of blast radius.**

- [x] **(code) NEW 2026-09-16 — HIGH: `/tenants/:id/update-config` (and `GET /tenants/:id/config`) have no server-side role check; any authenticated front_desk login can hijack live call transfers and overwrite attested legal disclosure text.** **CLOSED 2026-09-16, PR #522** (along with the staffing-CRUD MEDIUM item below and the full consolidated table further down — one batch). `src/routes/tenants.ts` (~lines 324-376, shifted from ~302-350 by PR #517's unrelated `GET /tenants` column-allowlist fix landing above these routes in the same file — re-verified 2026-09-16, gap itself unchanged): both routes gate only on `requireAuth` + tenant-match-or-super-admin (`req.auth?.tenant_id === id`, else `requireSuperAdmin`-equivalent check) — verified directly against the code, there is no `req.auth.role` check anywhere in either handler. `UpdateConfigSchema` (~lines 50-121) lets **any authenticated tenant user, owner or front_desk, no distinction**, write: `forward_phone` (the live call-transfer destination — every future "talk to a person" call routes wherever this points), `call_disclosure` + `disclosure_attested` (the owner's legally-attested caller-disclosure text, meant to affirm the owner's own state-law compliance — see the schema comment at line ~104), `checklist_preset_id` / `checklist_overrides` (booking_mode, message_mode, disabled conversation blocks — what the AI will and won't do on every call), `tts_voice`/style flags, `owner_phone`, `logo_url`, `business_type`.
  - **Concrete failure:** a front_desk-role account (receptionist login) with a valid JWT can call `POST /tenants/:id/update-config` directly (devtools, a saved request replay, no elevated access needed) and it succeeds today. They could silently redirect `forward_phone` to any number they choose (live call-transfer hijacking — a "talk to a person" caller ends up wherever the front-desk account pointed it, with nothing in the UI to reveal the change), overwrite the legal disclosure text the owner specifically attested to (the attestation stamp `call_disclosure_attested_by`/`_at` records who attested, not who is authorized to change it afterward), or reconfigure what the AI agent does on every single call.
  - The dashboard hides this **client-side only**: `OutlookLayout.tsx`'s `isFrontDeskOnly` (verified — `role === 'front_desk' && !isAdmin`) excludes the `setup`/`ai-insights` tabs from front_desk nav and snaps a stale-URL front-desk session back to `dashboard`. The route itself enforces nothing — the UI restriction is cosmetic, not a security boundary.
  - **Same root-cause pattern as the already-tracked staffing-CRUD gap above** ("MEDIUM: staffing CRUD (employees/shifts/resources) has no server-side owner/role check," from PR #508's audit pass) — both are "dashboard hides the tab, the route doesn't check the role" — but this one is materially higher impact: it reaches live call-routing and legally-attested disclosure text, not just staff/schedule records. **Fix both in the same batch, or at minimum land this one first** given the blast radius (call hijacking + legal-attestation integrity vs. staff-record tampering).
  - **Also found via the same audit, same shape, lower impact — fix together:** `src/routes/services.ts` (create/update/delete — verified: all three gate on `requireTenantId` only, no role check), `src/routes/skills.ts` (create/delete — same), `src/routes/mappings.ts` (all 4 assign/unassign routes — same). These only relink service/staff/skill assignments (same-tenant, reversible, no call-routing or legal-text impact), so they're lower severity than the update-config finding but identical root cause: a route that trusts the dashboard's client-side role hiding instead of checking `req.auth.role` itself.
  - Fix: add `role === 'owner'` gating (or equivalent) to `/tenants/:id/update-config` at minimum — `GET /tenants/:id/config` is lower urgency (a read, not a write) but should get the same review — and to the services/skills/mappings routes listed above, matching the existing pattern already used at `/customers/import` (`src/routes/customers.ts` ~line 243, shifted from ~230 by PR #517's super-admin-scoping fix landing above it in the same file, `role === 'owner'` check with the comment "bulk PII writes are not a front-desk operation").
